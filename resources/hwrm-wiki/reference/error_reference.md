# Common Error Messages Reference

> A guide to understanding and resolving frequent hard-crashes and log errors generated by the Homeworld Remastered engine. Found in your `HwRM.log` file.

---

## 1. Engine & Rendering Crashes

**Error:** `"Invalid type for first arguement"` (or similar `Invalid type for [N]th arguement`)
- **Source:** Usually points to `setEngineBurn`, `setEngineGlow`, or `setEngineTrail` in `.ship` files.
- **Cause:** You passed a parameter with the wrong data type (e.g., an Integer instead of a Float, or missing a comma in an array). The HWRM engine is strictly typed during initialization. 
- **Fix:** Cross-reference your ship's engine definitions against a vanilla ship file to verify parameter order and type.

**Error:** `"group '%s' not found. Can't play NIS '%s'"`
- **Source:** Campaign / Level logic (`NISPlayFromGroup`).
- **Cause:** The engine attempted to trigger a Non-Interactive Sequence (Cutscene) focused on a specific SobGroup, but that SobGroup doesn't exist or is empty.

## 2. Gamerule & Level Crashes

**Error:** `"could not find sobgroup (%s)"`
- **Source:** Common in `CPU_AddDefendSobGroup` or Gamerule logic.
- **Cause:** You attempted to issue an order to a SobGroup string identifier that was never created via `SobGroup_Create`.

**Error:** `"Invalid inner value, check .level file"` / `"Invalid centre value, check .level file"`
- **Source:** Level loading (`setWorldBoundsInner`, `setWorldBoundsOuter`).
- **Cause:** The coordinate bounds defining the playable map area are mathematically invalid (e.g., the inner bound is larger than the outer bound).

## 3. Silent Crashes (No Log Output)

HWRM frequently crashes to the desktop without writing an error to `HwRM.log`. Common causes include:

- **Ship Script Ordering:** Calling `StartShipWeaponConfig` before `LoadModel` in a `.ship` file.
- **Missing Families:** Referencing a `BuildFamily` or `AttackFamily` on a ship that is not explicitly registered in `scripts/familylist.lua`.
- **Lua Syntax Errors in AI:** Using Lua 5.0+ syntax (`#table_name`) in the AI or Level scopes, which strictly run Lua 4.0 (`getn(table_name)`).
- **Missing Build Prerequisites:** Having a ship in `build.lua` whose `ThingToBuild` string does not exactly match the actual `.ship` filename.
