# HWRM_FSFC: AI Architecture & Crash Prevention

This document details the specific AI architecture and safe-wrappers implemented for the FreeSpace: Fleet Command mod.

## 1. The "Safe Wrapper" Pattern
During the development of the Terran AI, we discovered that the HWRM AI engine is incredibly brittle when handling numeric IDs for ships and research. Passing an invalid type or an undefined ID string to a function like `IsResearchDone()` causes a fatal `parameter:` runtime crash.

All HWRM_FSFC AI scripts MUST use the established safe wrapper pattern before invoking engine functions:

```lua
-- Safe check for research
function Util_CheckResearch_Terran(id)
    if (id ~= nil and type(id) == "number") then
        if (IsResearchDone(id) == 0 and IsResearchAvailable(id) == 1) then
            return 1
        end
    end
    return nil
end

-- Safe check for ship counts
function NumSquadrons_Terran(id)
    if (id ~= nil and type(id) == "number") then
        return NumSquadrons(id)
    end
    return 0
end
```

## 2. Ship-Based Research Progression
Unlike vanilla HWRM, the FSFC mod strictly enforces sequential tech progression based on **military production** rather than just buying research nodes. 

In `ai_upgrades.lua`, the AI is gated from researching the next tier of tech until it actually produces units from the previous tier:

```lua
-- Only research corvette tech if we've actually built enough fighters to use the tech
if NumSquadrons_Terran(TER_INTERCEPTOR) >= 2 then
    if Util_CheckResearch_Terran(TERRANCORVETTERESEARCH) == 1 then
        ResearchDemandAdd(TERRANCORVETTERESEARCH, 50)
    end
end
```

## 3. ID Constants
Always use the all-caps hashed constants generated by the engine, not string literals.
- `ter_pegasus` -> `TER_PEGASUS`
- `CorvetteProduction` -> `CORVETTEPRODUCTION`
